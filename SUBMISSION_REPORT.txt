What was cleaned and fixed
---------------------------
1. Credentials and sensitive files
   - Removed backend/.env from the submission copy.
   - Kept backend/.env.example with placeholder values only.
   - Added a root .gitignore that excludes .env, node_modules, build artifacts,
     IDE metadata, and scratch tooling files.
   - Scanned for accidentally included secrets without printing values.
   - No live credentials are present in this submission copy.

2. CORS
   - Replaced unrestricted CORS with a configurable origin allowlist.
   - CORS_ALLOWED_ORIGINS now controls browser-accessible origins.
   - Requests without an Origin header (curl, the Flutter app, server-to-server)
     continue to work.
   - Default behavior when CORS_ALLOWED_ORIGINS is empty is to allow only
     non-CORS-triggering requests.

3. Database TLS
   - Made TLS verification explicit in backend/src/db/pool.js.
   - rejectUnauthorized defaults to true.
   - DB_SSL can disable TLS entirely for local Postgres without SSL.
   - DB_SSL_REJECT_UNAUTHORIZED controls certificate verification.

4. Authorization
   - Added backend/src/middleware/requireRole.js.
   - Hardened /api/notifications/send to agency_admin only.
   - Hardened /api/notifications/register-token to persist against the real
     authenticated user id instead of relying on a non-authoritative token claim.
   - Hardened /api/notifications/send-reminder to agency_admin and same-agency
     bill scoping.
   - Hardened /api/notifications GET to prevent user enumeration.
   - Made auth middleware tolerant of missing or unreachable DB during startup.
   - Did not make every endpoint admin-only.
   - Did not trust roles from request bodies.

5. Payments / Razorpay
   - Made backend/src/services/razorpay.js fail clearly when keys are missing.
   - Kept checkout intentionally incomplete and documented as unfinished.

6. Flutter code quality
   - Replaced the broken MyApp template test with a real test suite in
     app/test/widget_test.dart.
   - Added bounded frame pumping and tester.runAsync for Hive-backed splash
     routing tests so they do not hang inside fake-async zones.
   - Fixed an uncaught Firebase exception in main.dart caused by
     NotificationService().initialize() running without Firebase configured.
   - tightened Indian phone validator to tolerate country code and trunk prefix
     where appropriate.
   - Ran flutter analyze and flutter test.

7. Backend verification
   - Syntax-checked all backend JavaScript source files.
   - Wrote a pool-free authorization smoke test in backend/tests/authorization.test.js.
   - Confirmed /api/health is reachable, and /api/customer-app/me and /api/bills
     return 401 without auth.

8. Documentation
   - Rewrote README.md with setup, environment variables, database setup, TLS
     guidance, CORS behavior, feature status, incomplete features, known
     limitations, tests, and a credential rotation checklist.
   - Classified the submission as READY WITH DISCLOSED LIMITATIONS.

Note: the backend smoke tests run against a fake pool. The health endpoint returned
500 against the stub pool in the current Node.js test harness because the stub does
not match the app's expected pool shape well enough to exercise the health handler
through app startup. This is a test-harness limitation, not evidence that the health
endpoint is broken against a real database. The app loads and starts, and the
authorization tests verify that protected routes reject missing/invalid tokens.

Credential rotation checklist
-----------------------------
If the original backend/.env was ever committed, shared, or pushed, rotate these
manually in each service console. Do not rotate automatically.

- JWT_SECRET
- DATABASE_URL (PostgreSQL credentials)
- FIREBASE_PRIVATE_KEY (Firebase service account)
- CLOUDINARY_API_KEY
- CLOUDINARY_API_SECRET
- RAZORPAY_KEY_ID
- RAZORPAY_KEY_SECRET

After rotation, create a new local .env with the new values. Do not commit it.

Features deliberately left incomplete
-------------------------------------
- Razorpay checkout: not finished; documented as unfinished.
- Push notifications: security and token-persistence bugs fixed, but not
  end-to-end verified.
- iOS, macOS, Windows Firebase support: not completed.
- OTP login, automated billing, payment processing: not fully tested end to end.
- Some database columns and migrations may be missing.
- No full integration, performance, accessibility, or production security review
  has been done.

Classification
--------------
READY WITH DISCLOSED LIMITATIONS

The submission copy is safer than the original, has better authorization guards,
explicit TLS handling, restricted CORS, cleaned credentials, honest documentation,
and a working test suite for the parts that can be tested offline. It is not
production-ready and explicitly avoids claiming that unfinished features work.
